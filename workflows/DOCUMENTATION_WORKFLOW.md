# Documentation Workflow

## Steps
1. Identify which requirements, architecture, database, security, API, deployment, and operations documents are affected by the change.
2. Inspect actual implementation and test evidence.
3. Update canonical documents in the application repository.
4. Keep metadata, status, owner, source commit, and dates accurate.
5. Update ADRs for material decisions and changelog/release notes for shipped changes.
6. Mark superseded content; do not leave contradictory active guidance.
7. Check links, file references, diagrams, terminology, and traceability.
8. Select non-sensitive approved/current documents for ChatGPT Project Sources.
9. Record remaining unknowns and documentation debt.

## Exit criteria
Documentation describes the current verified state, or clearly labels gaps and planned design. Project Sources are not treated as canonical version control.
