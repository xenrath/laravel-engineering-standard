# Project Initialization Workflow

## Inputs
Project purpose, stakeholders, repository access, existing documentation, runtime/environment evidence, constraints.

## Steps
1. Create the application ChatGPT Project and select memory behavior deliberately.
2. Apply Master Project Instructions and fill only verified configuration.
3. Inspect repository structure, branch/status, Composer files, frontend package files, migrations, tests, configuration templates, CI, and deployment evidence.
4. Identify actual framework/runtime versions and dependencies.
5. Understand business purpose, actors, modules, integrations, data sensitivity, and critical workflows.
6. Compare existing documentation with implementation; mark unknowns and discrepancies.
7. Create minimum project documents using templates; do not fill gaps with guesses.
8. Establish risk profile, applicability, exceptions, owners, and baseline.
9. Add selected approved, non-sensitive documents to Project Sources.
10. Produce baseline assessment and prioritized next actions.

## Outputs
Project Overview, Project Status, verified stack inventory, initial architecture/database/security views, requirements backlog, known issues, and open questions.

## Exit criteria
Owners and scope identified; evidence sources recorded; major risks visible; no critical secret leakage; next work prioritized.
