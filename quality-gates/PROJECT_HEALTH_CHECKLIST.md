# Project Health Checklist

Review periodically and after major incidents/releases.

## Product and requirements
- [ ] Scope, stakeholders, requirements, and acceptance criteria current.
- [ ] Legacy/obsolete behavior and unresolved assumptions identified.

## Architecture and code
- [ ] Architecture and ADRs match implementation.
- [ ] Dependencies and module boundaries remain understandable.
- [ ] Technical debt is visible and prioritized.

## Data and security
- [ ] Schema and data dictionary current.
- [ ] Authorization matrix and threat model reviewed.
- [ ] Vulnerabilities and secrets exposure addressed.
- [ ] Retention, backup, and restore controls verified.

## Quality and operations
- [ ] Tests and CI quality gates reliable.
- [ ] Monitoring, alerting, logs, and incident ownership effective.
- [ ] Performance/capacity reviewed against real usage.
- [ ] Deployment and rollback/recovery runbooks current.

## Governance
- [ ] Documents have owners/status and no stale conflicting sources.
- [ ] Exceptions have owners and expiry/review dates.
- [ ] Project Sources contain only current, useful, non-sensitive references.
