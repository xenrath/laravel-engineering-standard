# Changelog

All notable changes to Laravel Engineering Standard are documented here.

## [1.1.0] - 2026-11-19

### Added
- AI context and untrusted-content governance.
- Architecture, Laravel coding, database, API, frontend, security, testing, DevOps, performance, and documentation standards.
- Requirements, business process, use case, module, component architecture, data dictionary, API, security architecture, authorization matrix, ADR, deployment, backup/recovery, known issue, and technical debt templates.
- Project initialization, requirements, architecture, code review, security review, CI/CD, incident response, and documentation workflows.
- Definition of Ready/Done and review, security, release, and project-health quality gates.
- Engineering, Laravel, and security reference catalogs.

### Changed
- Separated document lifecycle, implementation lifecycle, and approval lifecycle.
- Clarified evidence hierarchy, applicability, risk-based tailoring, and exception governance.
- Strengthened Git, tool execution, secrets handling, dependency, migration, and production-operation safeguards.
- Aligned README, manifest, and cross-document references.

### Retained
- Core project overview/status, system architecture, database design, and session handover concepts from v1.0.

### Validation
- Package file inventory and ZIP integrity checked.
- Cross-reference and placeholder checks performed as part of packaging.
- No Laravel application repository or production environment was tested by this release.
